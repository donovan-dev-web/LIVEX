Ce document indique **où obtenir de l'aide** sur LIVEX et **comment signaler
un problème**. Pour contribuer au code, voir [`CONTRIBUTING.md`](CONTRIBUTING.md).

## Ouvrir une issue (canal principal)

Toute demande d'aide passe par les **issues GitHub** du dépôt
[donovan-dev-web/LIVEX](https://github.com/donovan-dev-web/LIVEX/issues),
avec le modèle adapté :

| Situation | Modèle à utiliser |
| :-- | :-- |
| Comportement inattendu ou erreur | 🐛 Signaler un bug |
| Nouvelle fonctionnalité ou amélioration | ✨ Demande de fonctionnalité |
| Question ou correction sur la documentation | 📚 Question / correction documentation |
| Proposition de décision d'architecture | 🧭 Proposition d'ADR |

Merci de **rechercher d'abord une issue existante** avant d'en ouvrir une
nouvelle, et d'indiquer dans votre message :

- la version concernée (cf. [`VERSIONING.md`](VERSIONING.md)) ;
- le composant (SYNE, ECHOS, PRISM, Launcher, syne-mock) ;
- les étapes pour reproduire le problème, si pertinent.

## Contact direct

Pour une question qui ne relève pas d'une issue (projet, collaboration,
demande professionnelle), utilisez la page contact du portfolio :
**<https://donovan-dev-web.vercel.app/contact>**.

## Hors périmètre de l'assistance

- **résultats scientifiques** : les observations d'un run sont des données à
  analyser, pas des preuves (voir [`docs/presentation/VISION.md`](docs/presentation/VISION.md)) ;
- **`syne-mock`** : outil de développement des contrats, non équivalent à SYNE
  et impropre à toute validation scientifique (voir [`syne-mock/README.md`](syne-mock/README.md)) ;
- **support utilisateur de production** : LIVEX est en V0.1, stade de
  recherche ; il n'existe pas de canal de support garanti.
