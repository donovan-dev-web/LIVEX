10 Architecture · Results

What is claimed is measured.

A numerical claim is only valid if it can be replayed. This page brings together the method, tests, benchmarks and what remains, to date, unmeasured.

10.1 Method and reproducibility

Replay a run identically.

A run is defined by four ingredients: a seed (64-bit integer), a configuration, an engine version and an initial state. With equal seed and version, SYNE replays the same trajectory bit-for-bit; the run identifier (run-<seed>-<12hex>) carries the seed, which ECHOS does not derive itself.

SYNE benchmarks print an FNV-1a checksum of the state (population, ticks, then oneid;x;y;energy line per entity, sorted by ID). Two passes with the same seed produce the same checksum: this is the operational proof of determinism.

Known gap at 1,000 entities. The scalability target is not met at this scale (≈ 6 t/s vs ≥ 10). Optimising perception and batch-processing events is the identified task; it does not block V0.1, whose scenarios run at 100 agents or fewer.

10.4 What is not yet measured

What we do not claim.

Calibration of constants

Need and threshold constants are based on inherited values, not calibrated. No reference campaign has yet validated these settings.

Sensitivity of the emergence index

The weights of the composite score are published but untested; a sensitivity analysis remains to be done.

Statistical protocol

The number of runs needed for a difference between configurations to be more than an observation is not determined.

Single reference machine

Performance, determinism and acceptance rely on a single machine and a single runtime. A single measurement is not a law.

10.5 Limits to interpretation

A figure is not a conclusion.

Tick throughput measures speed, not relevance. Test coverage measures the extent of checks, not the correctness of the model. An emergence index measures dispersion, not proof. Every result here carries its version, date and source; a figure without a source is not published.
