12 Télécharger · Installation

Démarrer LIVEX depuis les sources.

Aucun installeur n'est distribué. Voici comment faire tourner la pile depuis le dépôt, en local — c'est un environnement de développement, pas un service public.

À lire d'abord. Les services de développement s'exécutent en local (127.0.0.1) et ne sont pas durcis pour une exposition publique.

12.1 Prérequis

Ce qu'il faut avoir.

OutilVersionPour
.NET SDK10.0.4xxMoteur SYNE
Python3.11+ECHOS (observation, API)
Node.js20+syne-mock (intégration)
Unreal Engine5.8PRISM et le plugin PRISM-LDK (hors portée V0.1)
curl—Vérifications de disponibilité
12.2 Démarrage rapide

La pile en une commande.

Depuis la racine du dépôt :

./scripts/dev-stack.sh

Le script prépare l'environnement Python, compile SYNE, puis démarre dans l'ordre l'API ECHOS (port5000), SYNE (contrôle 5181, WebSocket 5180) et l'ingestion ECHOS. Il ne lance aucune simulation : SYNE reste à l'état Idle jusqu'à la commandeStart.

La documentation de l'API est alors sur http://127.0.0.1:5000/docs.

12.3 Sans moteur complet

Le mock pour l'intégration.

Pour avancer sur l'intégration Unreal sans démarrer SYNE :

cd syne-mock
npm ci
npm start -- config_prism.json

Le mock suit le contrat d'observabilité SYNE, mais simplifie la délibération et le pathfinding : il sert aux tests d'intégration, pas aux résultats scientifiques.

12.4 Ports locaux

Tout reste en local.

ServiceAdresseRôle
SYNE WebSocket127.0.0.1:5180Snapshots et événements d'un run piloté.
SYNE HTTP127.0.0.1:5181Contrôle du serveur et démarrage des runs.
API ECHOS127.0.0.1:5000Runs, métriques et analyses (API seule).
syne-mock127.0.0.1:5180/5181Serveur d'intégration (lancé séparément).
12.5 Tests

Vérifier que tout tourne.

# SYNE
cd syne && dotnet test Syne.sln --configuration Release

# ECHOS (depuis la racine)
echos/.venv/bin/python -m pytest -q

# Launcher
cd launcher && dotnet test Launcher.Tests.Unit

▲Expérimental Les chemins sont donnés à titre indicatif et suivent le dépôt de développement.
