    Namespace Simulation.Core.Communication

    Classes

    CommunicationState

    État de communication d'une entité (COMMUNICATION_PROTOCOL.md §7) : file sortante (bornée par maxSendsPerTick), file entrante (bornée par maxReceivesPerTick) et ensemble "déjà relayé" anti-boucle.

    V0.1 : la file entrante est consommée comme trace d'activité du tick (la révision des croyances par messages arrive avec l'analyse/les besoins sociaux) — la réception ajuste la confiance par la matrice de relations et marque l'interaction (COMMUNICATION_PROTOCOL.md §7).

    CommunicationSystem

    Système de communication par pulsations lumineuses publiques (SYNE-050 → 054, COMMUNICATION_PROTOCOL.md, décisions n°7-10). Exécuté en une passe par tick (performance.batchCommunication, PERFORMANCE.md) après le pipeline cognitif, dans un ordre causal strict :

    1. Diffusion : chaque entité (identifiant croissant) émet ses messages sortants (cap maxSendsPerTick) — portée transmissionRange + ligne de vue ; toute entité dans la portée reçoit, quelle que soit la cible (publicité, interception — décision n°8).
    2. Relais : chaque entité relaye les messages compris (cap partagé avec les envois) tant que hops < maxHops, avec dégradation de confiance × hopConfidenceDecay (10 %/hop — décision n°10).

    Coûts énergétiques (décision n°9) : envoi sendEnergyCost + payload × sendEnergyPayloadFactor, réception receiveEnergyCost + payload × receiveEnergyPayloadFactor, appliqués via BodyNeeds.ExertEnergy.

    Déterminisme : aucun tirage du PRNG global ; l'incompréhension (5 %) et les identifiants de message dérivent de hash SplitMix64 stables (DETERMINISM.md §3).

    Message

    Message échangé par pulsation (COMMUNICATION_PROTOCOL.md §3) : MessageId | SenderId | Type | Payload | Confidence | Hops | Timestamp(tick).

    • Confidence : confiance de transmission du message, dégradée de 10 %/hop à chaque relais (décision n°10). La confiance du récepteur envers l'émetteur ajuste la confiance à la réception (COMMUNICATION_PROTOCOL.md §7).
    • Hops : nombre de relais déjà effectués (bordures par maxHops).

    Déterminisme : le MessageId est un hash stable (SplitMix64) de (senderId, tick, séquence) — pas de dépendance au PRNG global (DETERMINISM.md §3).

    MessageReceived

    Réception d'un message (y compris interception — toute entité dans la portée reçoit).

    MessageSent

    Activité de communication d'un tick — alimente l'observabilité (message_sent / message_received, API_CONTRACTS.md §2.2) et les traces pour ECHOS (heatmap de communication, NetworkCentrality...).
