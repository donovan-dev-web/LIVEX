## 3. Corrections appliquées

### 3.1 Contenu et données

- Suppression des chiffres figés en dur dans les pages : versions des
  composants (`VERSION_TABLE` / `VERSION_TABLE_EN`), état CI
  (`PROJECT_STATE.ci`), tests et couverture (`PROJECT_STATE.tests`,
  `PROJECT_STATE.coverage`) dans `getting-started`, `versions`, `technique/echos`
  et `technique/resultats` (FR et EN).
- Séparateur décimal français respecté (`91,32 %` et non `91.32 %`).
- Note de bas de page d'accueil remplacée : les captures ne sont plus
  présentées comme des « emplacements à remplacer » mais comme des relevés datés
  du développement.
- `getting-started` (FR/EN) : ajout de la note Windows (Git Bash / WSL,
  `echos/.venv/Scripts/python.exe`) et des versions issues des données.
- `etat-du-projet` (FR/EN), `monographie` (FR/EN), `getting-started` (FR/EN) :
  nouvelles pages, listées dans la navigation, le pied de page, le plan du
  site, `llms.txt` et la documentation.
- Monographie : liste des chapitres partagée entre FR et EN via
  `src/data/monograph.ts` (plus de duplication), boutons « sommaire général » et
  « dossier complet », mention explicite que les chapitres sont en français.
- Documentation EN : ajout du lien vers le portail de la monographie (le lien
  n'existait qu'en français).
- `llms.txt` : libellés « Versions », « Monographie » et « Monograph » alignés
  sur le contenu réel.

### 3.2 Accessibilité

- En-têtes de tableaux Markdown : ajout de `scope="col"` via un plugin
  `hast` local (`satteriTableScope`, `astro.config.mjs`) — Astro 7 n'installe
  plus `@astrojs/markdown-remark` par défaut, le plugin `rehype` hérité
  faisait échouer le build.
- `aria-current="page"` sur la dernière miette de fil d'Ariane.
- Recherche modale : piège de focus, `Échap`, `Ctrl/Cmd+K`, restitution du
  focus sur le bouton d'ouverture (corrigé : le focus revient toujours au
  bouton, même si l'activation ne vient pas du pointeur).
- Sous-menus d'en-tête : ouverture au clic uniquement, `aria-expanded` /
  `aria-controls` fiables, `Échap` ferme et rend le focus.
- JSON-LD `Article` déplacé dans le `<head>` (prop `jsonLd` de `BaseLayout`) ;
  seul le `BreadcrumbList` reste dans le corps.
- 404 : un seul `h1` (`.sr-only`), titres visuels en paragraphes.
- Tableaux : `scope="col"` sur toutes les en-têtes, y compris les tableaux
  écrits à la main en Astro.
- `prefers-reduced-motion` respecté, focus visible, contrastes vérifiés.

### 3.3 SEO

- `canonical` explicite pour la 404 (`/LIVEX/404.html`) et `canonical` =
  `og:url` sur les 80 pages.
- URL JSON-LD `WebSite`/`Organization` corrigées (`.../LIVEX/`, plus la racine
  du domaine).
- `hreflang` : les articles du journal (FR uniquement) ne déclarent **plus**
  d'alternate anglais vers une page qui n'en est pas la traduction
  (`alternates={{}}`) ; le journal anglais reste une page d'état.
- `title` dans la fenêtre 25–66 caractères sur les 80 pages (nouvel attribut
  `seoTitle` optionnel dans la collection `actualites` : le `<title>` et l'Open
  Graph sont raccourcis, le H1 reste le titre complet).
- `description` entre 120 et 165 caractères partout.
- Manifeste PWA : `start_url` et `scope` **relatifs** (`"./"`), donc valides
  sous n'importe quel `base` (le build CI à la racine ne renvoie plus de 404
  d'icône).
- Sitemap : 79 URL, la 404 exclue, `hreflang` réciproques.
- Feed RSS : liens absolus cohérents avec la production.

### 3.4 Performance

- Images d'articles : syntaxe Markdown relative vers `src/assets/captures/`

- CSS et JS de la recherche chargés **à l'ouverture** de la modale, pas au

- Lighthouse 100/100/100/100, LCP 1,5 s, CLS 0.

### 3.7 Texte, encodage et formulation (passe corrective du 21/10/2026)

Une passe complète sur les 80 pages (FR, EN et articles) a été conduite sur le
HTML produit, pas sur les sources.

| Défaut | Cause | Correction |
| :-- | :-- | :-- |
| Entités HTML affichées en clair (« D&eacute;terminisme », « &rarr; ») | **Les attributs Astro (`title`, `text`, `cta`) ne décodent pas les entités** : `&` est ré-échappé en `&amp;` et le navigateur affiche la chaîne littérale. Le texte enfant, lui, était décodé — d'où l'incohérence. | Toutes les entités hors `<code>`/`<pre>` sont écrites en UTF-8 direct ; les 23 occurrences non décodées dans le HTML produit sont tombées à 0. |
| Chaînes françaises sur les pages anglaises | Les pages EN lisaient `PROJECT_STATE.coverage`, `PROJECT_STATE.ci`, `PROJECT_STATE.windows` et `PROJECT_STATE.observedDate` (chaînes FR) au lieu du miroir `PROJECT_STATE_EN`. | Bascule sur le miroir localisé : pourcentages au point, « jobs green », « Windows support validated locally since 8 Oct 2026 », dates anglaises. |
| Fil d'Ariane et libellés d'accessibilité en français sur 3 pages EN | `lang="en"` n'était pas transmis à `PageHeader` (ni à `CardLink` sur l'accueil EN) : le fil d'Ariane affichait « Accueil » et pointait vers l'accueil FR. | `lang="en"` transmis ; contrôle ajouté à l'audit (0 régression). |
| Tirets et libellés incohérents | `V0.2 - en préparation`, titres `LIVEX - …`, `Contribuer / Contribuer`, `Monographie complète`. | Tiret cadratin partout, `Portail des chapitres`, `Guide de contribution` / `Contribution guide`, lien vers la page d'état du projet ajouté à la documentation EN (parité FR/EN). |
| Note périmée sur l'index Architecture | « Emplacements de capture : remplacés par des captures réelles de la version publiée » alors que les captures sont déjà là et qu'aucune version n'est publiée. | « Emplacements réservés : les captures réelles figurent sur la page de chaque composant. » |
| Accord et redites | « mêmes arborescence et adresses », légende « 13/13 jobs verts » qui répétait le chiffre au-dessus. | « mêmes arborescences et adresses » ; légende des CI reformulée (« Intégration continue au vert, relevé du … »). |

## 6. Rejouer les contrôles

```bash
cd site
npm ci
npm run check        # 0 erreur, 0 avertissement
npm run build        # 80 pages + index Pagefind
npm run check:links  # liens internes

# Performance (build et preview doivent partager le même base)
SITE_URL=http://localhost:4321 BASE_PATH=/ npm run build
SITE_URL=http://localhost:4321 BASE_PATH=/ npx @lhci/cli@0.14.0 autorun
```

> `astro preview` relit `astro.config.mjs` **au démarrage** : sans
> `BASE_PATH=/`, le serveur sert `/LIVEX/` et renvoie 404 sur
> `http://localhost:4321/`. Les variables doivent être présentes pour le build
> **et** pour le preview (`DEPLOYMENT.md` §4 et §7).
