# I18N.md — internationalisation (FR/EN)

**Composant** : Site vitrine (LIVEX)
**Statut** : [STABLE]
**Dernière mise à jour** : 21 octobre 2026
**Dépend de** : `../../site/src/i18n/ui.ts`, `../../site/src/utils/url.ts`, `../../site/astro.config.mjs`

---

## 1. Principe

- Le **français est la langue source** : il est servi à la racine (`/`).
- L'**anglais est un miroir** publié sous `/en/`, avec **la même arborescence,
  les mêmes slugs et les mêmes ancres** que le français.
- Aucune **redirection automatique** : le choix de langue est explicite
  (sélecteur de l'en-tête, liens `hreflang`). Un moteur de recherche ne peut
  donc pas rediriger un visiteur francophone vers l'anglais.
- Les **noms techniques** (SYNE, ECHOS, PRISM, Launcher, `tick`, `seed`,
  `run_id`, …) ne sont jamais traduits.

## 2. Modèle et configuration

Dans `site/astro.config.mjs` :

```js
i18n: {
  defaultLocale: 'fr',
  locales: ['fr', 'en'],
  routing: { prefixDefaultLocale: false },
}
```

Dans `site/src/i18n/ui.ts` :

| Export | Rôle |
| :-- | :-- |
| `languages` | Nom affiché de chaque langue (`fr` → « Français », `en` → « English »). |
| `Lang` | Type `'fr' \| 'en'`. |
| `defaultLang` | `'fr'`. |
| `publishedLangs` | `['fr', 'en']` — langues réellement générées (hreflang, sélecteur). |
| `ui` | Dictionnaire de chaînes par langue. |
| `useTranslations(lang)` | Retourne `t(key)` avec repli sur le français. |
| `getLangFromUrl(url)` | Déduit la langue d'une URL rendue (tient compte de `base`). |
| `stripLangFromPath(path)` | Retire `base` et le préfixe `en/` d'un chemin. |

## 3. Construction d'URL

`site/src/utils/url.ts`, deux fonctions :

| Fonction | Signature | Effet |
| :-- | :-- | :-- |
| `url` | `url(path = '', lang = 'fr')` | Préfixe `base` (`/LIVEX/`) puis `en/` si `lang === 'en'`. Renvoie tel quel si le chemin est une URL absolue (`http(s)://`, `//`) ou une ancre (`#…`). |
| `absoluteUrl` | `absoluteUrl(path = '', lang = 'fr')` | Version absolue (canonical, JSON-LD, RSS). |

Conséquences :

- **Toute** URL interne passe par `url()` ; jamais de chemin codé en dur
  (le `base` casse sur GitHub Pages).
- `url('', 'fr')` → `/LIVEX/` ; `url('faq/', 'en')` → `/LIVEX/en/faq/`.
- Les URL externes et les ancres traversent `url()` sans modification.

## 4. Niveaux de traduction

Le choix du niveau conditionne le bandeau et reflète la qualité de la
traduction.

| Niveau | Signification | Pages | Bandeau |
| :-- | :-- | :-- | :-- |
| **1** | Relu par un humain | Accueil, Comprendre, Limites, Architecture, Télécharger, Installation, FAQ, Mentions légales, Confidentialité | non |
| **2** | Traduction automatique relue | SYNE, ECHOS, PRISM, Launcher, Résultats, Versions, État du projet, Démarrer en 5 minutes, Documentation, Monographie, À propos, Auteur, Émergence, Glossaire, Feuille de route, Suivre, Participer, Transparence IA, Accessibilité, Licence, Plan du site | **oui** |
| **3** | Français uniquement, signalé | Articles du journal | — |

Les pages de niveau 2 passent `translated` au `BaseLayout`. La page
`/en/actualites/` (niveau 3) affiche un état « journal en français » et
renvoie vers le flux français.

## 5. Bandeau de traduction

Quand `translated` est vrai, `BaseLayout` insère au-dessus de l'en-tête :

> « Traduction automatique, relue — le français fait foi. »
> + lien « Lire la version française → ».

Chaînes : `translation.notice` et `translation.link` (`ui.ts`). Style `.tnote`.
Le lien pointe vers la version française de **la même page**.

## 6. Alternates `hreflang`

`BaseLayout` émet, pour chaque page, un lien `alternate` par langue publiée
plus un `x-default` (français), calculés à partir du chemin sans langue
(`stripLangFromPath`) :

```html
<link rel="alternate" hreflang="fr" href="…/LIVEX/<chemin>/" />
<link rel="alternate" hreflang="en" href="…/LIVEX/en/<chemin>/" />
<link rel="alternate" hreflang="x-default" href="…/LIVEX/<chemin>/" />
```

Le sitemap reproduit ces alternates (`@astrojs/sitemap` avec `i18n`,
`SEO.md` §4). Les pages **françaises portent donc aussi** l'alternate anglais
(réciprocité).

Exception : les **articles du journal** (niveau 3) passent
`alternates={{}}` à `BaseLayout`. Aucun `hreflang` anglais n'est déclaré et
le sélecteur de langue n'offre que le français, plutôt que de pointer vers
une page anglaise qui n'est pas la traduction de l'article. Le journal anglais
(`/en/actualites/`) reste accessible et renvoie explicitement vers les
articles français.

## 7. Sélecteur de langue et page 404

- Le sélecteur (`Header.astro`) propose `FR` / `EN` pour **chaque** page qui a
  un équivalent, en pointant vers le **même chemin** dans l'autre langue.
  `langLinks` permet de surcharger la cible ; une page sans équivalent
  (article du journal) n'affiche que sa langue.
- La **404 est unique et bilingue** : `404.astro` contient les deux variantes
  et un script en ligne choisit selon le chemin ; il n'existe pas de
  `/en/404`.
- Le flux RSS **reste français**. Les pages anglaises qui le citent renvoient
  vers `url('actualites/feed.xml', 'fr')`.

## 8. Règles d'écriture

- Ajouter une chaîne d'interface **dans les deux langues** (`ui.fr` et
  `ui.en`) et l'utiliser via `t(key)`.
- Ne pas mettre de texte français dans une page `src/pages/en/`.
- Conserver les acronymes et identifiants techniques.
- Les données bilingues (composants, tableaux de versions) ont un miroir
  `*_EN` dans `site/src/data/` (`CONTENT.md`).
- Après ajout d'une page anglaise, vérifier `npm run check` et le build.
