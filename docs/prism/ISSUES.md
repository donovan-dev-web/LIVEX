## 1. Objectif

Backlog complet du composant PRISM V2, **source unique de création des cartes Kanban**. Chaque issue : ID, titre, labels, priorité (P0 bloquant, P1 important, P2 souhaitable), dépendances, critère d'acceptation. Les milestones suivent les phases de `ROADMAP.md`. Les issues des autres composants sont listées en §4 (identifiants réservés).

## 2. Règles

- PRISM ne décide pas du comportement des agents ; aucune issue ne l'y autorise.
- Toute issue qui modifie un monde généré ou une règle met à jour `worldGenVersion`/`engineVersion` et les empreintes dorées dans la même PR.
- Toute issue touchant un contrat suit `API_CONTRACTS.md` §8.

Le pack minimal déclarant exactement les valeurs par défaut (16 / 3 / 256), les empreintes de run sont inchangées : campagne réduite épinglée verte (19/19 en Release), test de bout en bout `HostAppliesThePerceptionSettingsDeclaredByTheContentPack`, et graine 1 × 5 000 ticks × 3 bots rejouée après câblage qui reproduit exactement `24ae2cb3859fc0b8` / `a6dc178b93014432` / `f908a09792afd3f4`.

**Mesures du 3 novembre 2026 (Windows, Release, pack minimal, `prism-bots --timings`), conservées pour comparaison :** préparation d'un monde (`Prepare`, génération comprise) 21–27 s ; tick sans agent 53 ms ; tick avec un agent inactif 1,26–1,49 s, coût linéaire par agent (perception dominante) ; empreinte de run identique entre les builds Debug et Release sur la même graine.
